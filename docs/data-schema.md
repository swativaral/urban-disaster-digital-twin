# Common Data Schema

## 1. Purpose

This document defines the common data structure used by the
AI/ML, GIS, Routing, Backend and Frontend modules.

All modules must use the same field names and ID formats.

---

# 2. Zone Schema

A zone represents a monitored geographical area.

## Fields

| Field | Type | Description |
|---|---|---|
| zone_id | String | Unique zone identifier |
| name | String | Zone name |
| latitude | Float | Centre latitude |
| longitude | Float | Centre longitude |
| rainfall | Float | Rainfall value |
| elevation | Float | Elevation in metres |
| slope | Float | Terrain slope |
| drainage | Float | Drainage condition/value |
| population_density | Float | Population density |
| historical_flood | Integer | Historical flood indicator |
| risk_score | Float | Predicted risk score |
| risk_level | String | Current risk level |

## Example

```json
{
  "zone_id": "Z01",
  "name": "Zone A",
  "latitude": 18.5204,
  "longitude": 73.8567,
  "rainfall": 180,
  "elevation": 42,
  "slope": 2.1,
  "drainage": 0.35,
  "population_density": 8500,
  "historical_flood": 1,
  "risk_score": 87,
  "risk_level": "CRITICAL"
3. Road Schema

A road represents a route segment used by the routing engine.

Fields
Field	Type	Description
road_id	String	Unique road identifier
name	String	Road name
start_node	String	Starting graph node
end_node	String	Ending graph node
length_km	Float	Road length
travel_time_min	Float	Normal travel time
risk_score	Float	Current disaster risk
status	String	Current road status
geometry	GeoJSON	Geographic road geometry
Example
{
  "road_id": "R01",
  "name": "Main Road",
  "start_node": "N01",
  "end_node": "N02",
  "length_km": 1.8,
  "travel_time_min": 5,
  "risk_score": 10,
  "status": "OPEN"
}

9. Route Schema

A route represents a calculated path between two locations.

Fields
Field	Type	Description
route_id	String	Unique route identifier
source	String	Starting location
destination	String	Destination
road_ids	Array	Roads used in route
distance_km	Float	Total route distance
eta_minutes	Float	Estimated travel time
risk_score	Float	Route risk
status	String	Route status
Example
{
  "route_id": "RT01",
  "source": "LOC01",
  "destination": "H02",
  "road_ids": ["R01", "R05", "R08"],
  "distance_km": 4.5,
  "eta_minutes": 9,
  "risk_score": 12,
  "status": "SAFE"
}

15. Data Integration Rules
All modules must use the same entity IDs.
Field names must remain consistent across modules.
Risk scores must use a 0–100 scale.
Risk levels must use the predefined values.
Road status must be updated when a road becomes unsafe or blocked.
Routing must use the latest available road risk information.
Backend acts as the main communication layer between modules.
Frontend receives data through Backend APIs.
ML predictions must contain a timestamp.
Any schema change must be documented before integration.
